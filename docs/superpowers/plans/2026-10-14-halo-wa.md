# Soma HALO-WA implementation plan

> Execution: inline using executing-plans and TDD. User approved official HALO-WA architecture, configuration selection, preservation and verification of the MLP path.

Goal: add the official HALO-WA attention adapter to the existing Songling SsEval loop with frozen Soma observation VAE tokens.

Architecture: preserve the existing MLP implementation and learner. Register a separate halo_wa_policy and select a specialized HaloWALearner in the existing runtime. Reuse replay, feedback, actor publication and checkpoint infrastructure. Raw visual tokens remain in z_rl as [B,N,C]; the old path remains [B,D]. The controller boundary stays physical 14D absolute qpos.

Reference: YeanRoot/HALO-WA 611008193fd3438bf99cc8f8377858fbdfcb9555. Actor uses self/cross attention; critic cross attention and twin Q heads. Hidden width 512, chunk 12, official BC/TD3 losses. Preserve attribution and license. Soma is the approved backbone substitution; its action codec and visual layout differ from upstream GigaWA.

Constraints: envs/ali.yaml; interpreter /miniconda3/envs/ss-vidu/bin/python; task-local dependencies only. No hardware control, job submission, shared environment changes, commit or push. Existing feature branches are the delivery targets; isolated source snapshots are used for development and baseline comparisons.

## Review focus
1. Human actions must not replace the WA reference input on the HALO path.
2. Visual projection/position weights must train and publish with Actor; critic updates must not corrupt shared visual features.
3. Both replay streams must actually contribute half the batch, including small buffers.
4. Checkpoints must retain warmup, demo/replay RNG and feature identity; mismatches must fail.
5. Variable camera/history shapes must fail clearly before replay insertion; old MLP config and numerical behavior must stay unchanged.
